# Cloud Rosetta Design System

**The design lives in one file: [`data/design.yml`](../../../data/design.yml).**

`scripts/design.py` turns that file into the page's CSS custom properties. There is no second place
to edit. The guide carries cloud content only, so there is no design page in it; this skill and
`docs/design-system.md` are where the design is explained.

## The One Rule

> Never write a colour, font size, spacing value or radius anywhere except `data/design.yml`.

Everything else uses `var(--token)`. `scripts/check_design.py` fails the build if you bypass it,
and it runs in continuous integration.

## Before You Change Anything Visual

```bash
python scripts/build.py          # regenerate the page, drawings and Design page
python scripts/check_design.py   # prove nothing bypassed the token file
```

## How To Do Common Things

**Change a colour, size or spacing value.** Edit `data/design.yml`, rebuild. The stylesheet, the
drawings and the standalone SVG exports all follow. Do not touch the CSS.

**Add a new token.** Add it under the right group in `data/design.yml`, including a dark-theme
counterpart under `colour.dark` if it is a colour. Then reference it as `var(--your-token)`.
Every token defined must be used and every token used must be defined; the check enforces both.

**Add a component to the guide.** Write its CSS in `scripts/shell.html` using `var()` references.
If you need a value that does not exist yet, add the token first.

**The sidebar and tables follow shadcn/ui.** Their structure, states and dimensions were read from
the component source (`sidebar.tsx`, `table.tsx`) and reproduced without React. Markup uses the same
`data-slot` names as shadcn, so `sidebar-group`, `sidebar-menu-button`, `sidebar-menu-sub` and
`sidebar-menu-badge` mean what they mean there. Extend them in that vocabulary rather than inventing
new classes. Two deviations are recorded in `data/design.yml`: table cells wrap, and group labels
use the 14px floor instead of shadcn's 12px.

**Add or edit a diagram.** Diagrams are generated by `scripts/diagrams.py`. Colours come from
`PALETTE` and `NEUTRAL`, which are read from `data/design.yml` at import time. A standalone SVG
cannot read CSS custom properties, which is why the values are inlined there, and why they must
still be token values. Drawn text may not go below the `t-label` size.

## What The Check Enforces

Colours and font sizes are enforced. **Spacing is not yet**: the stylesheet held 145 pixel literals
for padding, gaps and widths before this was written down, and `check_design.py` does not inspect
them. New components should still take spacing from tokens, as the sidebar and table do for their
structural dimensions; hairline border widths such as `1px` are reasonable to leave literal.

| Rule | Why |
| --- | --- |
| No literal colour in `scripts/shell.html` | The stylesheet is generated around tokens; a literal cannot follow a theme change |
| No literal `font-size` in `scripts/shell.html` | Sizes come from the six-step scale |
| Every hex in `scripts/diagrams.py` is a value from `data/design.yml` | Drawings had silently drifted to a previous palette before this rule existed |
| No drawn text below the `t-label` size | Checked against the generated SVGs, because a size can reach the output through a helper default |
| No two labels overlap inside a drawing | Centred labels collide the moment boxes nest, which has happened twice |

## The Design Itself

Taken from the Elegant Themes blog, measured from computed styles at a 1280px viewport on
15 September 2026, not copied by eye.

- **Lato** throughout. Roboto Mono for code, identifiers and exam codes.
- **19px running text at a 1.9 line height.** Looser than most documentation, and the reason the
  page reads as calm.
- **Six sizes**, rounded to whole pixels because the source computes fractional values from
  multipliers.
- **Blue-tinted neutrals, never grey and never black.** Headings `--ink`, running text `--ink2`,
  secondary `--ink3`.
- **A 640px prose column** and **69px above every section**.
- **One accent**, hot pink, on fully pill-shaped actions. It appears nowhere else, so the primary
  action is never ambiguous.
- **One hue per cloud**, used identically in every table, diagram and card, and for nothing else.

## Archify

**Archify is not used on this project and is not installed. Do not install or suggest it.**
Every diagram comes from `scripts/diagrams.py`. Archify was evaluated and removed on
17 September 2026; the reasons are in
[`docs/reviews/2026-09-17-archify-evaluation.md`](../../../docs/reviews/2026-09-17-archify-evaluation.md).
The short version: its output ignores `data/design.yml`, it has no AWS, Azure or Google service
icons, and it cannot draw availability zones, so a subnet can only be drawn as a security group.

## Deviations Are Recorded, Not Made Silently

`data/design.yml` has a `deviations` list explaining each place this guide departs from its
source, and the Design page renders it. If you deviate, add an entry saying what and why. Four
exist today, including keeping monospace for code and keeping underlines on links, because
colour alone fails readers who cannot separate the blue from the surrounding navy.
